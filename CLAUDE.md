## Project Overview

**AlphaLoom** - 列ごとの候補文字から鍵を探すツール. A static web app: the user lists likely letters for each position (column) of a key in order of preference; the tool lists the combinations with the largest weights exactly and scores dictionary words against the columns. Given a Vigenère ciphertext, it builds the columns from letter frequencies and ranks dictionary words by how English the text decrypted with them looks. Main use: narrowing down a Vigenère key that is an English word. Input and dictionaries never leave the browser. Japanese and English UI.

Part of the "100 Security Tools with Generative AI" project (Day046).

## Architecture

- **index.html**: UI with three ARIA tabs (generator, dictionaries, usage). The generator tab starts with the optional ciphertext card. Meta CSP without `'unsafe-inline'`; hidden sections use the `hidden` attribute (no style attributes). Text carries `data-i18n` / `data-i18n-attr`
- **script.js**: UI entry (ES module). Builds column inputs, tables and the dictionary list with `textContent` only; no `alert`/`confirm`. Ciphertext flow: `estimateKeyLength` → `analyzeCipher` (fills the columns with the top letters and runs the generator) → `renderCipher`. Trial decryption columns appear only when the generator length equals the ciphertext key length
- **js/loom-core.js**: Pure logic (no DOM): `normalizeLetters`, `columnLetters`, `parsePattern`, `columnModel`/`buildColumns`, `countCombinations` (BigInt), `topCombinations`, `scoreDictionary`, `findWordsInKey`, `parseWordList`, `formatShare`, `toCsv`
- **js/vigenere.js**: Pure logic: `encryptVigenere`/`decryptVigenere`, `columnScores`/`rankColumns` (per-column log-likelihood), `scoreWordsByCipher` (dictionary words by log-likelihood per letter), `periodicIC`/`keyLengthCandidates` (threshold 0.058, same as Day044)
- **js/english.js**: Generated by `tools/build-english.mjs` from `tools/corpus/train-pg1342.txt`. Do not edit by hand
- **js/accuracy.js**: Generated by `tools/measure-accuracy.mjs` (fixed seed; evaluation text `tools/corpus/eval-pg98.txt`). Do not edit by hand; rerun the tool if the dictionaries or the scoring change
- **js/params.js**: `#text=` (preferred; not sent to the server, no URL length limit) or `?text=` (up to 10,000 chars) and `n` (1-20), the same format as Modular Text Divider (Day030). `#` wins; after reading, `urlWithoutHandoff` removes text and n from both. Outgoing links to Day017/Day030 use `#text=`
- **js/wordlists.js**: Built-in mini dictionary (222 words, same words as `wordlists/english-mini-223.txt`) and the bundled wordlist table. The large 12dicts list is bundled but not loaded by default
- **js/messages.js / i18n.js**: All UI strings in Japanese and English (same keys). Language: `?lang=` → saved choice (`alphaloom-lang`) → browser language. Logic returns keys and values only
- **js/tabs.js / theme.js / theme-init.js / file-check.js**: Tabs with arrow keys, light/dark theme, notice when opened via `file://`
- **style.css**: Color tokens on `:root`, dark overrides for `data-theme="dark"` and `prefers-color-scheme`

### Algorithms

1. **Column weights**: N letters get linear weights N..1 normalized to sum 1; a blank column is uniform over A-Z. A key's weight is the product of its column weights (all combinations sum to 100%). It is not the probability that the key is correct
2. **Top combinations**: best-first search over index tuples with a priority queue (each pop pushes the tuples advanced by one position in each column; visited set). Exact top-K regardless of the total (26^20 works); keys always have the chosen length. Ties are ordered alphabetically
3. **Dictionary scoring**: every dictionary word of the same length is scored by the product of its letters' column weights; words with a letter outside a column's candidates are dropped. Not limited to the kept top-K
4. **Partial matches**: dictionary words of 3+ letters contained in a candidate, found by looking up the candidate's substrings in a Set
5. **Ciphertext analysis**: per-column key letters ranked by the log-likelihood of the decrypted letters under English frequencies (+1 smoothing); dictionary words ranked by the sum of their per-column scores divided by the ciphertext length (about -2.90 for English, -3.83 for random letters); key length from the average column index of coincidence

See `ALGORITHM.md` for details (Japanese).

## Development Commands

- `npm test` — node:test, no dependencies, Node 22+. Runs in GitHub Actions on push and pull requests
- `node tools/build-english.mjs` / `node tools/measure-accuracy.mjs` — regenerate `js/english.js` / `js/accuracy.js` (about 30 s for the measurement)
- Serve over HTTP to run the UI: `python -m http.server 8000` → `http://localhost:8000/`. Chrome/Edge cannot load ES modules from `file://`; Firefox can, but bundled wordlists cannot be fetched there

## Key Implementation Notes

- Never use `innerHTML` for user-provided data. Tests forbid `innerHTML`, `.style.` and `alert`/`confirm` in the UI scripts
- Column inputs are normalized only when not composing (IME-safe: `input` with `isComposing` check plus `compositionend`)
- Bundled wordlists are fetched only from the fixed list in `js/wordlists.js` (no free-form paths)
- Links to other tools are built from the normalized ciphertext and open with `rel="noopener noreferrer"`
- Keep the README YAML metadata structure (keys, order, block lists) unchanged; `readme.test.js` checks it. README.en.md has no YAML block and must keep the same headings as README.md
